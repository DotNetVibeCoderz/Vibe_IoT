# Payload codecs: Protobuf, MessagePack, TLV

**Summary.** Transports move bytes; applications want values. `IPayloadCodec<T>` (in Abstractions) is the small
contract every codec implements — `ContentType`, `Encode(T)`, `Decode(bytes)` — so an MQTT bridge or a CoAP resource
can switch format without changing code. IoTCom.Net does not rebuild serializers: the adapters wrap the established
libraries and add the schema-less views you need when debugging traffic.

| Package | Codec | Schema-less view |
|---|---|---|
| `IoTCom.Net.Serialization.Protobuf` | `ProtobufCodec<T>` over Google.Protobuf generated types; length-delimited streams | `ProtobufWire.TryInspect` / `Describe`: field numbers, wire types, values, nested messages |
| `IoTCom.Net.Serialization.MessagePack` | `MessagePackCodec<T>` over MessagePack-CSharp (pass options with your resolver; source-generated for NativeAOT) | `MessagePackView.ToJson` / `Describe` |
| `IoTCom.Net.Serialization.Tlv` | `TlvFormat` (fixed 1/2/4-byte tag and length, either byte order) and `BerTlv` (ISO 8825 / EMV / ISO 7816: multi-byte tags, long lengths, constructed tags) | `BerTlv.Describe` |
| `IoTCom.Net.Serialization.SenML` | `SenMLPayloadCodec(cbor: false \| true)` | — |

The TLV package is part of the IoTCom.Net meta-package; Protobuf and MessagePack are separate so that their
dependencies stay optional (Sparkplug B brings Google.Protobuf on its own).

## Quickstart

```csharp
using IoTCom.Net.Serialization.Protobuf;
using IoTCom.Net.Serialization.MessagePack;
using IoTCom.Net.Serialization.Tlv;

IPayloadCodec<Telemetry> codec = new ProtobufCodec<Telemetry>();          // Telemetry generated by protoc / Grpc.Tools
await mqtt.PublishAsync("plant/line1/telemetry", codec.Encode(reading));

ProtobufWire.TryInspect(unknownBytes, out var fields);                    // no .proto needed
foreach (var f in fields) Console.WriteLine($"#{f.Number} {f.Value}");

var json = MessagePackView.ToJson(packedBytes);                           // {"temp":27.5,"rh":71}

var fci = BerTlv.Decode(Convert.FromHexString("6F148407A0000000031010A5095004564953419F3800"));
var label = fci[0].Find(0x50);                                            // "VISA"
var simple = TlvFormat.Simple.Encode([TlvItem.Primitive(0x01, [0x2A])]);  // 01 01 2A
```

## Tools

```bash
iotcom payload protobuf "08 96 01 12 02 68 69"   # tree of fields
iotcom payload msgpack 81A174CB4035800000000000   # JSON
iotcom payload ber-tlv 6F14…                      # frame lane + tree
iotcom payload tlv 01012A02024F4B                 # 1-byte tag, 1-byte length
```

The VS Code extension's frame viewer offers `protobuf`, `msgpack` and `ber-tlv` as decoders.

## Testing

Protobuf tests compare bytes with the well-known `Timestamp` type, round-trip length-delimited streams and inspect
nested messages without a schema; printable strings are shown as text. MessagePack tests check exact bytes and the
JSON view; TLV tests cover both byte orders, overruns, an EMV FCI with multi-byte tags and long-form lengths.

## Limitations

Protobuf inspection cannot know field names or tell a packed repeated field from bytes. BER-TLV does not accept
indefinite lengths. CBOR beyond SenML is not covered yet.
