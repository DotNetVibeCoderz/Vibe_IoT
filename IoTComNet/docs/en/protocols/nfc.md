# NFC / NDEF

**Summary.** NFC tags are stickers, cards and key fobs that phones and readers power by field and read within a few
centimetres. They hold NDEF messages: a URI to a manual, a text with an asset number, Wi-Fi credentials, an app link.
On a PC, contactless readers expose tags through PC/SC. `IoTCom.Net.Protocols.Nfc` provides:

- **NDEF codec** (`NdefMessage`, `NdefRecord`):
  - Text (UTF-8 and UTF-16), URI with the prefix codes, Smart Poster, MIME, absolute URI and external types
  - Android Application Records and Wi-Fi credentials (WSC, `WifiCredential`; the key is never shown by `ToString`)
  - short and long records, ids, and chunked records joined on parse; the frame lane (`NdefMessage.Describe`)
- **Type 2 tags** (`Type2Tag`, `Type2TagClient`) — NTAG213/215/216 and MIFARE Ultralight:
  - UID pages with check bytes, the capability container, TLV parsing (NULL, lock and memory control, NDEF, terminator),
    3-byte TLV lengths, and a page map of every byte (`Type2Tag.Map`)
  - reading through the PC/SC storage-card commands GET DATA, READ BINARY and UPDATE BINARY
  - writing NDEF only when allowed, only the pages that change, empty-then-fill so a tag pulled away mid-write never
    holds half a message, and never pages 0–3; tags whose capability container says read-only are refused
- **Readers**:
  - `PcscNfcReader` on winscard (Windows), pcsc-lite (Linux) and the PCSC framework (macOS); `Open()` prefers
    contactless readers (PICC, ACR122, Omnikey 5x22…) over contact readers and virtual smart cards
  - `VirtualNfcReader` with `VirtualType2Tag`, which answers the same APDUs, for tests, notebooks and the Gallery

Following the design, NFC is managed C# only: PC/SC is an operating-system API, and NDEF is a small codec checked
against `/conformance/ndef.json`, generated by an independent Python reference.

## When to use it

- Asset and maintenance tags: open a manual, record a service visit, check a serial number.
- Commissioning: hand out Wi-Fi credentials or configuration with a tap.
- Access and identity: read UIDs of cards and fobs at a gate or a kiosk.
- Preparing batches of tags with a URI or text from a PC.

## Installation

```bash
dotnet add package IoTCom.Net.Protocols.Nfc --prerelease    # also part of the IoTCom.Net meta-package
```

On Linux install `pcscd` and `libpcsclite1` (and the reader's driver, for example `libacsccid1`); Windows and macOS
include PC/SC.

## Quickstart

```csharp
using IoTCom.Net.Protocols.Nfc;

var reader = PcscNfcReader.Open();                       // or Open("ACR122")
await using var card = await reader.WaitForTagAsync();
var tag = new Type2TagClient(card);
Console.WriteLine(Convert.ToHexString(await tag.GetUidAsync()));
foreach (var record in (await tag.ReadNdefAsync())?.Records ?? []) Console.WriteLine(record);
```

Writing:

```csharp
var writer = new Type2TagClient(card, new NfcTagOptions().AllowWrites());
await writer.WriteNdefAsync(new NdefMessage([NdefRecord.Uri("https://example.com/asset/42"), NdefRecord.Text("Asset 42")]));
```

## Safety

Writing replaces what is on the tag, so writes are off until `NfcTagOptions.AllowWrites()`, and `iotcom nfc write`
needs `--allow-write` and a confirmation. The library never writes the UID, lock or capability container pages and
never locks a tag: locking is permanent, so do it with the tag vendor's tools when you mean it. A Wi-Fi credential on
a tag can be read by anyone who taps it; use a guest or commissioning network.

## Tools

```bash
iotcom nfc readers                                  # PC/SC readers
iotcom nfc read --sim --dump                        # a simulated NTAG213, NDEF and every page
iotcom nfc read --reader ACR122
iotcom nfc write --uri https://example.com/asset/42 --text "Asset 42" --reader ACR122 --allow-write
iotcom nfc decode "D101085502 6E78702E636F6D"
```

The VS Code extension decodes NDEF (`ndef`). Gallery: *NFC asset tags*.

## Testing

Codec tests cover:
- the NFC Forum URI example (https://www.nxp.com), prefix codes, and Text records in UTF-8 and UTF-16 with a byte-order
  mark;
- a message with a Smart Poster, text, Wi-Fi credential, external type, Android app record and a 300-byte long record;
- chunked records, the empty message, and malformed messages (missing MB or ME, TNF 7, stray chunks, truncation).

Tag tests cover:
- UID check bytes and capability containers for the three NTAG sizes;
- TLV parsing with lock-control and NULL TLVs, 3-byte lengths, and a message that does not fit;
- reading, refused and allowed writes, unchanged messages writing nothing, protected pages, and the page map;
- a read-only tag, a blank NTAG216 filled with 700 bytes, a removed tag, and waiting for a tag;
- a real PC/SC call that lists readers or explains why it cannot.

The 30 shared vectors run in the C# suite.

## Limitations

Only NFC Forum Type 2 tags are read and written. MIFARE Classic (with its keys), Type 4 (DESFire, ISO 14443-4 NDEF
applications) and Type 5 (ISO 15693) are not supported yet. Readers that do not implement the PC/SC part 3
storage-card commands are not supported either: some readers need vendor escape commands. NTAG password protection,
the originality signature and counters are not exposed.
