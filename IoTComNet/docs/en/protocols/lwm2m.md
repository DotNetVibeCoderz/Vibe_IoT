# OMA LwM2M

**Summary.** Lightweight M2M (LwM2M) is the device-management standard for constrained and cellular (NB-IoT, LTE-M)
devices. It runs on CoAP. A device, the LwM2M client, registers with a server, keeps that registration alive, and
exposes its state as numbered objects from the OMA registry: Device (3), Location (6), Temperature (3303), Light
Control (3311) and hundreds more. The server reads, writes, executes and observes them by path, for example
`/3311/0/5851` for a dimmer. `IoTCom.Net.Protocols.Lwm2m` builds on IoTCom.Net's own CoAP stack and provides:

- `Lwm2mClient`, the device side:
  - registration (`POST /rd` with endpoint name, lifetime, binding and object links), automatic updates at 80 % of the
    lifetime with re-registration when the server forgot the device, and deregistration
  - Read, Discover, Write (replace and partial update), Execute and Observe on object instances (`Lwm2mInstance` with
    `Set`, `OnWrite` validators and `OnExecute` handlers)
  - Write-Attributes `pmin`/`pmax` driving notifications, observation cancel, and `AbortAsync` to simulate a device
    that drops off the network
- `Lwm2mServer`, the management side:
  - registrations with update and expiry (`Registered`, `Updated`, `Deregistered` with the reason)
  - `ReadAsync`, `DiscoverAsync`, `WriteAsync`, `ExecuteAsync`, `WriteAttributesAsync` and `ObserveAsync`
  - read-only by default: Write and Execute need `AllowWrites()`
- Content formats `Lwm2mContent`: TLV (11542), plain text, opaque, SenML JSON (110) and SenML CBOR (112), with types
  from `Lwm2mRegistry`; the TLV frame lane (`DescribeTlv`).
- `Lwm2mStreetLightSimulator`: a street light with Device (including Reboot), Location, LED driver temperature and
  Light Control (dimmer checked to 0–100 %).

Following the design, LwM2M is C# on IoTCom.Net's CoAP (no Rust twin). The TLV codec is checked against
`/conformance/lwm2m.json`, generated by an independent Python reference.

## When to use it

- Managing fleets of NB-IoT, LTE-M or other constrained devices: inventory, configuration, reboots, telemetry.
- Building a device that should work with an existing LwM2M platform (Eclipse Leshan, AVSystem Coiote, operator
  device-management platforms).
- Testing a server against simulated devices, or a device against a scripted server.

## Installation

```bash
dotnet add package IoTCom.Net.Protocols.Lwm2m --prerelease    # also part of the IoTCom.Net meta-package
```

## Quickstart

A device:

```csharp
using IoTCom.Net.Protocols.Lwm2m;

await using var client = Lwm2mClient.Create(o => { o.EndpointName = "urn:dev:sensor:42"; o.UseServer("lwm2m.example.com"); });
client.AddInstance(3).Set(0, "Acme").Set(1, "TH-1").Set(2, "42").OnExecute(4, _ => { /* reboot */ return true; });
var temperature = client.AddInstance(3303).Set(5700, 21.5).Set(5701, "Cel");
await client.ConnectAsync();          // register
temperature.Set(5700, 22.0);          // observers are notified
```

A server:

```csharp
await using var server = Lwm2mServer.Create(o => o.UseUdp(5683));
server.Registered += r => Console.WriteLine(r);
await server.StartAsync();
// later
var device = await server.ReadAsync("urn:dev:sensor:42", Lwm2mPath.Parse("/3/0"));
await server.WriteAttributesAsync("urn:dev:sensor:42", Lwm2mPath.Parse("/3303/0/5700"), pmin: 10, pmax: 300);
await using var watch = await server.ObserveAsync("urn:dev:sensor:42", Lwm2mPath.Parse("/3303/0/5700"), v => Console.WriteLine(v[0]));
```

## Safety

Writes and Execute change what devices do; Reboot and firmware resources take them offline. The server refuses them
until `Lwm2mServerOptions.AllowWrites()`. On the device side, `OnWrite` validators reject values a resource must not
take (the simulator's dimmer refuses 150 %), and resources without Write access answer 4.05. This package runs over
plain CoAP on UDP 5683: production deployments use DTLS (port 5684) with pre-shared keys or certificates, which is a
separate item on the roadmap. Do not expose an unprotected server to the internet.

## Tools

```bash
iotcom lwm2m demo                                   # server and street light in-process
iotcom lwm2m demo --allow-write
iotcom lwm2m serve --observe /3303/0/5700           # a read-only server on UDP 5683
iotcom lwm2m client --server 127.0.0.1              # the street light against any LwM2M server
iotcom lwm2m decode 3/0/6 8606410001410105          # TLV
```

On Git Bash, write paths without the leading slash (`3/0/6`) or set `MSYS_NO_PATHCONV=1`: the shell turns `/3/0/6`
into a Windows path. The VS Code extension decodes TLV (`lwm2m-tlv`); captures use UDP 5683 so Wireshark shows the
CoAP exchange. Gallery: *Street lights over LwM2M*.

## Testing

Codec tests cover:
- paths, nesting and invalid paths;
- the Device example from the LwM2M specification, decoded and re-encoded byte for byte, also wrapped in an object
  instance;
- minimal integer sizes, float or double, booleans, times, object links and unsigned values, with wrong lengths
  rejected;
- SenML JSON and CBOR round trips, plain text values, and malformed TLV and SenML.

Session tests run the server and the street light over an in-memory network:
- registration with the object links, and reads in TLV, plain text, SenML JSON and SenML CBOR;
- discover, a missing object (4.04), and reading an executable resource (4.05);
- read-only refusals, then writes (replace, partial update, SenML), a dimmer value refused by the device (4.00), a
  write to a read-only resource (4.05), and Execute;
- observation with pmin/pmax: a notification on change and another after pmax without change, then cancel;
- updates at 80 % of the lifetime, deregistration, and expiry of a device that drops off the network.

The 19 shared TLV vectors (including six malformed payloads) run in the C# suite and are re-encoded byte for byte.

## Limitations

There is no DTLS yet, no bootstrap server (`/bs`), no Create or Delete of object instances, no Send operation, no
queue mode or SMS binding, and no LwM2M JSON (11543) format. Large values are not split with CoAP block-wise
transfers by this layer. Notifications use the attributes `pmin` and `pmax`; `gt`, `lt` and `st` are not evaluated.
