# IEC 60870-5-104

**Summary.** IEC 60870-5-104 ("IEC 104") is the telecontrol protocol between SCADA masters and substations, RTUs,
renewable plants and grid gateways, on TCP port 2404. A controlling station (the master) starts data transfer, runs a
general interrogation to learn every value, then receives only changes, each with a CP56Time2a time tag. It operates
breakers, switches, tap changers and set points with commands, usually as select-before-operate.
`IoTCom.Net.Protocols.Iec104` provides:

- `Iec104Client`, a controlling station:
  - STARTDT/STOPDT, and a table of the latest value of every point (`Points`, `PointReceived`)
  - general and group interrogation, counter interrogation, read
  - single, double and regulating step commands and set points (float, scaled, normalized), direct or
    select-before-operate, waiting for the activation confirmation and termination
  - clock synchronisation
  - read-only by default: commands, set points and clock sync need `AllowCommands()`
- `Iec104Server`, a controlled station:
  - a point table (`Define`, `Update`) with spontaneous time-tagged changes to every connection that started data
    transfer, groups and counters
  - command handlers per address (`MapCommand`), optional mandatory select-before-operate with a select timeout
  - negative answers for unknown types, causes, common addresses and object addresses, and end of initialisation
- The APCI link shared by both: N(S)/N(R) sequence checks, the k and w windows, the t1/t2/t3 timers, TESTFR.
- The codec: `Iec104Apdu`, `Iec104Asdu`, `Iec104Object`, `Cp56Time2a`, 38 type identifications, `Iec104Framing` and the
  frame lane (`Iec104Apdu.Describe`).
- `Iec104SubstationSimulator`, a 20 kV feeder bay RTU:
  - breaker, disconnector and earthing switch with interlocks, and a protection trip
  - measurements, an on-load tap changer, an energy counter and a reactive power set point

The codec has a fuzzed Rust twin (`rust/crates/iotcom-iec104`) checked against the same `/conformance/iec104.json`
vectors, which come from an independent Python reference.

## When to use it

- Building a SCADA, historian or grid-analytics front end that reads substations and RTUs.
- Gateways from IEC 104 to MQTT, OPC UA or a database, or from field protocols (Modbus, DLMS) to an IEC 104 master.
- Testing a SCADA master against a simulated RTU, or an RTU against a scripted master.


## Quickstart

```csharp
using IoTCom.Net.Protocols.Iec104;

await using var scada = Iec104Client.Create(o => o.UseTcp("10.0.0.5"));      // port 2404, CA 1, read-only
await scada.ConnectAsync();                                                  // STARTDT
foreach (var p in await scada.InterrogateAsync()) Console.WriteLine(p);      // general interrogation
scada.PointReceived += p => Console.WriteLine(p);                            // spontaneous, time-tagged changes
```

Operating equipment:

```csharp
await using var op = Iec104Client.Create(o => o.UseTcp("10.0.0.5").AllowCommands());
await op.DoubleCommandAsync(5001, on: false, selectBeforeOperate: true);    // open the breaker: select, execute, termination
await op.SetpointAsync(6001, 1.5);                                           // C_SE_NC_1
```

A station:

```csharp
await using var rtu = Iec104Server.Create(o => o.UseTcp(2404));
rtu.Define(2001, Iec104TypeId.MeasuredFloat, 20.1, "Busbar voltage (kV)");
rtu.Define(1001, Iec104TypeId.DoublePoint, 2, "Breaker");
rtu.MapCommand(5001, Iec104TypeId.DoubleCommand, c => { if (!c.IsSelect) rtu.Update(1001, c.Command.Value, cause: Iec104Cause.ReturnRemote); return true; });
await rtu.StartAsync();
rtu.Update(2001, 20.3);    // sent as M_ME_TF_1 with a time tag
```

## Safety

IEC 104 commands open and close breakers on live networks. The client is read-only by default and throws
`ReadOnlyModeException` for commands, set points and clock synchronisation until `AllowCommands()` is called.
`iotcom iec104 command` needs `--allow-write` and asks for confirmation on real stations. Use select-before-operate for
switchgear, and only connect to stations you are authorised to operate. IEC 104 has no security of its own; on real
networks, run it inside a VPN or with IEC 62351 TLS terminated by a gateway.

## Tools

```bash
iotcom iec104 serve                                 # the feeder bay RTU on TCP 2404
iotcom iec104 gi -h 127.0.0.1                       # general interrogation table (--group 1–16, --counters)
iotcom iec104 monitor --sim                         # interrogation, then spontaneous changes
iotcom iec104 read 2001 --sim
iotcom iec104 command double 5001 off --sbo --sim --allow-write
```

## Testing

Codec tests use byte examples:
- the six U frames and S frames;
- the classic C_IC_NA_1 activation;
- time-tagged floats with CP56Time2a (including invalid and summer-time bits, and 31 February rejected);
- step positions with the transient bit, normalized and scaled values, and double points in a sequence (SQ = 1);
- counters with sequence, carry and adjusted flags, commands with select, and set points;
- malformed APDUs and ASDUs, and a stream split with noise.

Session tests run the simulator over the in-memory transport:
- general, group and counter interrogation, read, and an unknown address;
- the protection trip arriving as time-tagged spontaneous data;
- select-before-operate enforced, a breaker moving through "intermediate", and interlocks refusing unsafe switching;
- tap changer, set point limits, an unknown command address, clock synchronisation, and read-only refusals;
- a 300-point interrogation with k = 2 and w = 1, TESTFR after t3;
- a station closing the link when acknowledgements stop (t1) and on a sequence error;
- negative answers for unknown type, cause and common address.

The 52 shared vectors (including 9 malformed frames) run in both the C# and the Rust test suites, and the Rust suite
also re-encodes every valid frame. The Rust codec was fuzzed for 1.6 million runs with no findings.

## Limitations

There is no file transfer, parameter loading (P_ME), C_RD with groups or redundancy group handling yet, and no
IEC 62351 security. Spontaneous changes are not buffered while no master has started data transfer. Cyclic (periodic)
transmission is left to the application (`Update(..., Iec104Cause.Periodic, force: true)`). The serial companion
IEC 60870-5-101 is not implemented.
