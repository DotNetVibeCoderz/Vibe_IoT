# EtherNet/IP (explicit messaging)

**Summary.** EtherNet/IP is the Common Industrial Protocol (CIP) over Ethernet, used by Rockwell/Allen-Bradley and
many other PLCs, drives and I/O. An originator (HMI, SCADA, gateway) opens TCP 44818, registers a session and sends
CIP requests inside SendRRData — "explicit messaging". Each request names an object with an EPATH (class, instance,
attribute) or, on Logix controllers, a symbolic tag. `IoTCom.Net.Protocols.EtherNetIp` provides:

- Codecs (sans-I/O): `EnipPacket` (24-byte encapsulation header, Common Packet Format, SendRRData helpers, frame
  lane), `CipPath` (logical 8/16/32-bit segments, padded symbolic segments, element indexes), `CipRequest`,
  `CipResponse` (general and additional status), `EnipIdentity` (ListIdentity item and Identity attributes) and
  `CipTagValue` (Logix elementary types BOOL…LREAL, arrays).
- `EnipClient`: RegisterSession/UnregisterSession, `RequestAsync` for any CIP service, Get_Attribute_Single,
  Get_Attributes_All, Set_Attribute_Single, `ReadIdentityAsync`, Logix Read Tag and Write Tag (elements and
  arrays), `ReadTagsAsync` in one Multiple_Service_Packet, ListIdentity, and Unconnected_Send routing to a backplane
  slot (`UseSlot(0)`). **Read-only by default.**
- `EnipDiscovery.ListIdentityAsync`: UDP broadcast discovery.
- `EnipAdapter`: a target for explicit messaging with sessions, ListIdentity over TCP and UDP, ListServices, and a
  message router serving the Identity object, Assembly objects (attribute 3), Multiple_Service_Packet,
  Unconnected_Send and symbolic tags with type, range and access checks.
- `EnipPlcSimulator`: a packaging-line controller (speed, conveyor, good/reject counters, seal temperature and set
  point, recipe, fault code, four zone temperatures, input assembly 100 and output assembly 150).

Following the design, the runtime is managed C#; the Rust crate `iotcom-enip` is a fuzzed twin of the codecs, and
both run the 28 vectors in `/conformance/enip.json` generated by an independent Python reference.

## When to use it

- Reading and writing Logix tags from .NET: dashboards, MES and historian connectors, OEE.
- Talking to drives, I/O blocks and other CIP devices through their objects and attributes.
- A test target for HMIs and gateways without a PLC (`EnipAdapter` or `iotcom enip serve`).

## Installation

```bash
dotnet add package IoTCom.Net.Protocols.EtherNetIp --prerelease    # also part of the IoTCom.Net meta-package
```

## Quickstart

```csharp
using IoTCom.Net.Protocols.EtherNetIp;

await using var plc = EnipClient.Create(o => o.UseTcp("192.168.1.20", EnipPacket.Port).UseSlot(0));   // read-only
await plc.ConnectAsync();
Console.WriteLine(await plc.ReadIdentityAsync());
CipTagValue speed = await plc.ReadTagAsync("Line_Speed");
foreach (var (tag, value, error) in await plc.ReadTagsAsync(["Count_Good", "Count_Reject", "Seal_Temp"]))
    Console.WriteLine($"{tag} = {value?.ToString() ?? error!.Message}");
```

Writes, after opting in:

```csharp
await using var hmi = EnipClient.Create(o => o.UseTcp("192.168.1.20", EnipPacket.Port).UseSlot(0).AllowWrites());
await hmi.ConnectAsync();
await hmi.WriteTagAsync("Seal_Setpoint", CipTagValue.Of(CipDataType.Real, 172));
```

A target of your own:

```csharp
await using var adapter = EnipAdapter.Create(o => { o.UseTcp(IPAddress.Any, 44818); o.UseUdp(44818); });
var level = adapter.AddTag("Tank_Level", CipTagValue.Of(CipDataType.Real, 42.5), writable: false);
await adapter.StartAsync();
level.Set(43.1);
```

## Safety

Tag and attribute writes change what machines do. The client refuses them until `AllowWrites()`; the CLI needs
`--allow-write` and asks before writing to a real controller, and the Gallery has a write lock. Writing to a running
Logix controller bypasses its program logic for that value — coordinate with the controls engineer. EtherNet/IP has no
authentication (CIP Security is not implemented); keep controllers on a separate network. `EnipAdapter` can refuse
every write with `WriteProtected`.

## Tools

```bash
iotcom enip demo [--allow-write]                                      # session, identity, tags in-process
iotcom enip discover                                                  # ListIdentity broadcast (--broadcast 192.168.1.255)
iotcom enip identity --host 192.168.1.20 --slot 0
iotcom enip read Line_Speed,Count_Good,Seal_Temp --host 192.168.1.20 --slot 0
iotcom enip read Zone_Temps --count 4 --sim
iotcom enip write Line_Speed REAL 90 --host 192.168.1.20 --slot 0 --allow-write
iotcom enip attr 0x01 1 7 --sim                                       # Get_Attribute_Single
iotcom enip serve                                                     # the simulated PLC on TCP/UDP 44818
iotcom enip decode "4C 06 91 0A 4C 69 6E 65 5F 53 70 65 65 64 01 00"
```

## Testing

Codec tests cover tag paths (program scope, members, elements, padding), typed values and overflow, and
Multiple_Service_Packet splitting. The 28 shared vectors cover encapsulation headers and CPF items, logical paths
with 8/16/32-bit segments, symbolic paths with padding, members and elements, Write Tag data, CIP replies with
additional status, the ListIdentity item, and malformed input of each kind; the Rust twin is fuzzed (`enip`).

Session tests run the client against the simulated PLC in-process: session and identity (all attributes, attribute 7,
ListIdentity), tag reads with elements and counts, unknown tags and out-of-range elements, a Multiple_Service_Packet
with one failing tag, read-only refusal, typed writes, wrong types and read-only tags, assembly get/set, routed
requests through Unconnected_Send, ListIdentity over UDP, and SendRRData without a session.

## Limitations

Implicit (class 1, cyclic I/O) messaging and Forward_Open connected messaging are Phase 3 items. Logix structures
(UDTs, STRING), Read Tag Fragmented for large arrays, tag browsing (Symbol Object), CIP Security and DLR are not
implemented. The adapter does not route Unconnected_Send further: it is always the destination.
