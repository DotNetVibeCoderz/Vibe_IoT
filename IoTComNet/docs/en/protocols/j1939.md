# SAE J1939

**Summary.** J1939 is the CAN protocol of heavy vehicles: trucks, buses, tractors, construction machines, gensets and
marine engines, usually at 250 or 500 kbit/s with 29-bit identifiers. Each identifier carries a priority, a parameter
group number (PGN) and the sender's address. A PGN packs suspect parameters (SPNs) with fixed scaling. Messages longer
than 8 bytes use the transport protocol, and nodes claim addresses with a 64-bit NAME.
`IoTCom.Net.Protocols.J1939` runs on any `ICanBus` (SocketCAN, slcan, gs_usb, PCAN, virtual) and provides:

- `J1939Node`:
  - address claim with NAME arbitration (the lower NAME wins; arbitrary-address-capable nodes move to a free address)
  - `MessageReceived` with decoded SPN values, and `Claims` (every address and NAME seen on the bus)
  - transport protocol in both directions: BAM broadcasts and RTS/CTS transfers (up to 1785 bytes) with the
    end-of-message acknowledgement, timeouts and aborts
  - `RequestAsync` (PGN 59904, answered by a single frame or by the transport protocol) and `Respond` to serve requests
  - listen-only mode (no claim, nothing transmitted, transfers between other nodes still reassembled) and read-only
    mode (requests only)
- `J1939Id` (29-bit identifiers, PDU1/PDU2, data page), `Pgn` constants, `J1939Name`, `TpConnectionMessage`.
- `J1939Spn`: decodes and encodes the SPNs of EEC1, EEC2, CCVS1, ET1, EFL/P1, LFE1, VEP1 and HOURS, handles "not
  available" and "error" values, and draws the frame lane (`Describe`).
- `J1939Dm1` / `J1939Dtc`: lamp status and trouble codes (SPN, FMI, occurrence count) for DM1 and DM2.
- `J1939EngineSimulator`: an engine ECU.
  - broadcasts EEC1 and CCVS1 every 100 ms, and ET1, EFL/P1, LFE1, VEP1 and DM1 every second
  - answers requests for the VIN, the component identification and the engine hours
  - can develop an oil leak (DM1 SPN 100 FMI 1, amber lamp)

The codec has a fuzzed Rust twin (`rust/crates/iotcom-j1939`) checked against the same `/conformance/j1939.json`
vectors, which come from an independent Python reference.

## When to use it

- Fleet telematics: engine speed, fuel rate, temperatures and trouble codes from a truck's diagnostic port.
- Workshop and test-bench tools that read the VIN, the component identification and DM1/DM2.
- Monitoring engines on generators, pumps, boats and agricultural machines.
- Simulating an ECU to test a dashboard, a logger or a gateway.

## Installation

```bash
dotnet add package IoTCom.Net.Protocols.J1939 --prerelease    # also part of the IoTCom.Net meta-package
```

## Quickstart

```csharp
using IoTCom.Net.Protocols.J1939;
using IoTCom.Net.Transport.Can;

await using var bus = await CanBus.OpenAsync("socketcan:can0", o => o.Bitrate = 250_000);   // or slcan:COM5, gsusb:, pcan:usb1
await using var node = J1939Node.Create(bus, o => o.ReadOnly = true);
node.MessageReceived += m =>
{
    if (m.Pgn == Pgn.Dm1) Console.WriteLine(string.Join("; ", J1939Dm1.Parse(m.Data).Dtcs));
    else if (J1939Spn.Knows(m.Pgn)) Console.WriteLine(m);   // "EEC1 from 0x00: …, Engine speed = 1168.625 rpm, …"
};
await node.StartAsync();                                   // claims 0xF9 (off-board diagnostic tool)

var vin = await node.RequestAsync(Pgn.VehicleIdentification);    // multi-packet answer via the transport protocol
Console.WriteLine(System.Text.Encoding.ASCII.GetString(vin.Data));
```

To listen without transmitting anything, use `J1939Node.Create(bus, o => o.ListenOnly = true)`. Also open the
adapter with `o.ListenOnly = true` if it supports that.

## Safety

Requests are harmless, but a J1939 node that claims an address takes part in the network. `ReadOnly = true` limits
the node to requests: `SendAsync` throws `ReadOnlyModeException`, so an application cannot send commands such as TSC1
torque/speed control. `ListenOnly = true` sends nothing at all, not even an address claim, which is the right choice
on a moving vehicle. The CLI monitor is listen-only; `request` and `claims` are read-only. Only connect to vehicles you
are authorised to work on.

## Tools

```bash
iotcom j1939 monitor --can sim                      # a simulated engine ECU
iotcom j1939 monitor --pgn eec1 --pgn dm1 --can socketcan:can0 --bitrate 250000
iotcom j1939 request vin --to 00 --can sim          # VIN over RTS/CTS
iotcom j1939 claims --can gsusb:                    # every address and NAME on the bus
```

The VS Code extension decodes J1939 frames (`j1939`). Gallery: *Truck cluster over J1939*.

## Testing

Codec tests cover:
- identifiers for PDU1, PDU2 and data page 1;
- the NAME bit layout;
- SPN decoding with "not available" values;
- DM1 with and without trouble codes, including 19-bit SPNs;
- transport protocol control messages and the frame lane.

Session tests run nodes on a virtual network:
- the engine's address claim and broadcasts;
- VIN over RTS/CTS, component identification over BAM, and engine hours in a single frame;
- the simulated oil leak raising DM1 and the amber lamp;
- a 1785-byte RTS/CTS transfer (255 packets);
- a node losing an address conflict and moving to a free address;
- read-only refusals, request timeouts, and a listen-only node that follows a transfer between two others.

The 28 shared vectors run in both the C# and the Rust test suites. The Rust codec was fuzzed for 2.9 million runs with
no findings.

## Limitations

The SPN table covers common engine PGNs only; unknown PGNs arrive with raw data. Not supported yet:
- the extended transport protocol (ETP, more than 1785 bytes);
- clearing trouble codes (DM3/DM11);
- NMEA 2000 fast packets;
- J1939-22 CAN FD multi-PG.
