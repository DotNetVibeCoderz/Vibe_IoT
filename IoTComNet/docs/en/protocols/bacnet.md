# BACnet/IP

**Summary.** BACnet (ASHRAE 135, ISO 16484-5) is the protocol of building management systems: chillers, air handling
units, VAV boxes, lighting panels and meters. A *device* holds *objects* (Analog Input, Analog Output, Analog Value,
Binary Input/Output/Value, Multi-state Value, …) whose *properties* (Present_Value, Units, Status_Flags, …) a BMS
reads and writes. BACnet/IP (Annex J) carries it over UDP 47808. IoTCom.Net ships two packages, following the design's
answer for BACnet — an adapter **and** our own server API:

**`IoTCom.Net.Protocols.Bacnet`** (our own, trimmable and NativeAOT compatible):

- Codecs: `BacnetWriter`/`BacnetReader` (application and context tags, opening/closing tags, extended lengths),
  `BacnetPacket` (BVLC incl. Forwarded-NPDU and BVLC-Result, NPDU with network addressing, every APDU type) with a
  frame lane, and `BacnetServices` for Who-Is/I-Am, Who-Has/I-Have, ReadProperty, ReadPropertyMultiple,
  WriteProperty, SubscribeCOV and COV notifications.
- `BacnetDevice`: a BACnet/IP device. It answers Who-Is (range-checked, I-Am broadcast, optional unicast), Who-Has,
  ReadProperty (array indexes), ReadPropertyMultiple (ALL/REQUIRED/OPTIONAL and per-property errors), WriteProperty
  and SubscribeCOV (confirmed with retry or unconfirmed notifications, lifetimes, COV increments), rejects unknown
  services and aborts segmented requests and over-long answers.
- `BacnetObject`: analog, binary and multi-state inputs, outputs and values with their required properties, a
  16-level priority array and relinquish default for commandable objects, out-of-service and fault status flags, and
  data-type and range checks that become the standard error codes.
- `BacnetAhuSimulator`: an air handling unit controller (fan command and proof, chilled-water valve and outdoor-air
  damper on their own loops unless overridden, temperatures, CO₂, static pressure, set points, occupancy, filter alarm).

**`IoTCom.Net.Adapters.Bacnet`** (adapter over ela-compil's BACnet library, MIT, pinned 4.0.0):

- `BacnetIpClient`: Who-Is discovery, ReadProperty, ReadPropertyMultiple, WriteProperty with priorities
  (**read-only by default**), SubscribeCOV with callbacks (confirmed notifications are acknowledged), using IoTCom's
  BACnet types. Its transport bridge runs the library over any IoTCom datagram transport, so it works on the
  in-memory network as well as on real UDP. The library is not annotated for trimming, so the adapter is not
  trimmable or AOT compatible and is not in the meta-package.

The test suite runs the adapter's client against IoTCom's own device — two independent BACnet implementations. The
codecs are also checked against `/conformance/bacnet.json`, generated by an independent Python reference.

## When to use it

- Reading and commanding BMS points from .NET: dashboards, energy reports, fault detection, analytics.
- Exposing your own equipment or gateway as a BACnet device a BMS can discover (`BacnetDevice` with your objects).
- Testing BMS integrations against a simulated air handling unit.

## Installation

```bash
dotnet add package IoTCom.Net.Protocols.Bacnet --prerelease   # server API (also in the IoTCom.Net meta-package)
dotnet add package IoTCom.Net.Adapters.Bacnet --prerelease    # client
```

## Quickstart

A device of your own:

```csharp
using IoTCom.Net.Protocols.Bacnet;

await using var device = BacnetDevice.Create(o => { o.DeviceInstance = 1001; o.DeviceName = "Chiller plant gateway"; });
var supply = device.Add(BacnetObject.AnalogInput(1, "CHW supply temperature", BacnetUnits.DegreesCelsius, 6.5));
var enable = device.Add(BacnetObject.BinaryOutput(1, "Chiller enable", relinquishDefault: false));
enable.Changed += (o, _) => Console.WriteLine($"enable → {o.FormatValue()} (priority {o.ActivePriority})");
await device.StartAsync();       // UDP 47808, I-Am broadcast
supply.Update(6.8);              // subscribers get a COV notification when the change reaches the COV increment
```

A client:

```csharp
using IoTCom.Net.Adapters.Bacnet;

await using var bms = BacnetIpClient.Create(o => o.AllowWrites());
await bms.ConnectAsync();
foreach (var d in await bms.DiscoverAsync()) Console.WriteLine(d);
var t = await bms.ReadPresentValueAsync(2604, BacnetObjectId.Parse("AI1"));
await using var cov = await bms.SubscribeCovAsync(2604, BacnetObjectId.Parse("AI1"), n => Console.WriteLine(n.Values[0].Values[0]));
await bms.WritePropertyAsync(2604, BacnetObjectId.Parse("BO1"), BacnetPropertyId.PresentValue, BacnetValue.Enumerated(0), priority: 8);
await bms.WritePropertyAsync(2604, BacnetObjectId.Parse("BO1"), BacnetPropertyId.PresentValue, BacnetValue.Null, priority: 8);   // relinquish
```

Where broadcasts do not reach the device (other subnets, containers), register it directly:
`bms.AddDevice(2604, new IPEndPoint(IPAddress.Parse("192.168.1.40"), 47808))`.

## Safety

Writes start and stop fans and pumps, open valves and change set points in occupied buildings. The client refuses
them until `AllowWrites()`; the CLI needs `--allow-write` and asks before writing to a real device, and the Gallery has
a write lock. Write at the priority your role owns (8 for a manual operator) and relinquish it when done — never
write at 1 or 2 (life safety). BACnet/IP has no authentication; keep BMS networks separate and never expose UDP 47808
to the internet. A device you build with `BacnetDevice` can refuse every write with `WriteProtected`. Vendor
identifier 999 is for tests; products need an identifier assigned by ASHRAE.

## Tools

```bash
iotcom bacnet demo [--allow-write]                         # device and client in-process
iotcom bacnet discover                                     # Who-Is on your network (--broadcast 192.168.1.255)
iotcom bacnet objects 2604                                 # objects, names, present values
iotcom bacnet read 2604 AI1                                # present value; or a property: priority-array, all
iotcom bacnet write 2604 BO1 inactive --priority 8 --allow-write
iotcom bacnet subscribe 2604 AI1,AI4,BI1                   # COV notifications
iotcom bacnet serve --device 2604                          # the simulated AHU on UDP 47808 for YABE or a BMS
iotcom bacnet decode 810A00110104000507 0C0C00000001 1955
```

Client commands take `--sim` (in-process unit) and `--address <ip>` (no discovery). Captures map BACnet to UDP 47808,
so Wireshark decodes them; the VS Code extension decodes `bacnet`. Gallery: *Air handling unit over BACnet*.

## Testing

Codec tests cover object identifiers, ReadProperty encoding, the priority array (command, lower priority ignored,
relinquish, value out of range, read-only properties, out-of-service inputs) and the frame lane. The 45 shared vectors
cover every application tag including long strings and bit strings, and BACnet/IP datagrams (Who-Is with and without
a range, I-Am, ReadProperty and its ACK, SimpleACK, Error, Reject, Abort, COV notification, Forwarded-NPDU,
BVLC-Result, SubscribeCOV) plus six malformed datagrams.

Interop tests run the adapter (ela-compil's client) against IoTCom's device on an in-memory network: discovery with and
without a matching range; the object list (whole and index 0); ReadPropertyMultiple with values, ALL and per-property
errors; unknown objects; read-only refusal, priority-8 command, priority array, relinquish, set points and an
out-of-range state; confirmed and unconfirmed COV with the initial notification, the COV increment and cancellation;
and the simulated unit's response to commands.

## Limitations

Segmentation is not supported (answers larger than the APDU are aborted, as the standard requires of a device without
it). There is no BBMD or foreign-device registration in the server, no routing between networks, no alarms and events,
schedules, calendars, trend logs, files, or CreateObject/DeleteObject in the server API, and no BACnet/SC or MS/TP.
The client adapter supports what the library supports; this package exposes discovery, reads, writes and COV.
