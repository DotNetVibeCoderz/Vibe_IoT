# SAE J1939

**Ringkasan.** J1939 adalah protokol CAN untuk kendaraan berat: truk, bus, traktor, alat berat, genset, dan mesin
kapal, biasanya pada 250 atau 500 kbit/s dengan identifier 29-bit. Setiap identifier membawa prioritas, parameter
group number (PGN), dan alamat pengirim. Satu PGN memuat suspect parameter (SPN) dengan skala tetap. Pesan lebih dari
8 byte memakai transport protocol, dan node mengklaim alamat dengan NAME 64-bit.
`IoTCom.Net.Protocols.J1939` berjalan di `ICanBus` apa pun (SocketCAN, slcan, gs_usb, PCAN, virtual) dan menyediakan:

- `J1939Node`:
  - klaim alamat dengan arbitrase NAME (NAME lebih kecil menang; node yang mampu alamat arbitrer pindah ke alamat
    kosong)
  - `MessageReceived` dengan nilai SPN yang sudah diurai, dan `Claims` (setiap alamat dan NAME yang terlihat di bus)
  - transport protocol dua arah: siaran BAM dan transfer RTS/CTS (hingga 1785 byte) dengan acknowledgement akhir
    pesan, timeout, dan abort
  - `RequestAsync` (PGN 59904, dijawab satu frame atau lewat transport protocol) dan `Respond` untuk melayani request
  - mode listen-only (tanpa klaim, tidak mengirim apa pun, transfer antar node lain tetap dirakit) dan mode
    hanya-baca (hanya request)
- `J1939Id` (identifier 29-bit, PDU1/PDU2, data page), konstanta `Pgn`, `J1939Name`, `TpConnectionMessage`.
- `J1939Spn`: mengurai dan menyandikan SPN dari EEC1, EEC2, CCVS1, ET1, EFL/P1, LFE1, VEP1, dan HOURS, menangani
  nilai "tidak tersedia" dan "error", serta menggambar frame lane (`Describe`).
- `J1939Dm1` / `J1939Dtc`: status lampu dan kode gangguan (SPN, FMI, jumlah kejadian) untuk DM1 dan DM2.
- `J1939EngineSimulator`: ECU mesin.
  - menyiarkan EEC1 dan CCVS1 tiap 100 ms, serta ET1, EFL/P1, LFE1, VEP1, dan DM1 tiap detik
  - menjawab request VIN, identifikasi komponen, dan jam operasi mesin
  - bisa mengalami kebocoran oli (DM1 SPN 100 FMI 1, lampu kuning)

Codec-nya punya kembaran Rust yang di-fuzz (`rust/crates/iotcom-j1939`) dan diperiksa dengan vektor
`/conformance/j1939.json` yang sama, yang berasal dari referensi Python independen.

## Kapan dipakai

- Telematika armada: putaran mesin, konsumsi BBM, suhu, dan kode gangguan dari port diagnostik truk.
- Alat bengkel dan meja uji yang membaca VIN, identifikasi komponen, dan DM1/DM2.
- Memantau mesin pada genset, pompa, kapal, dan mesin pertanian.
- Menyimulasikan ECU untuk menguji dasbor, logger, atau gateway.

## Instalasi

```bash
dotnet add package IoTCom.Net.Protocols.J1939 --prerelease    # juga bagian dari meta-package IoTCom.Net
```

## Mulai cepat

```csharp
using IoTCom.Net.Protocols.J1939;
using IoTCom.Net.Transport.Can;

await using var bus = await CanBus.OpenAsync("socketcan:can0", o => o.Bitrate = 250_000);   // atau slcan:COM5, gsusb:, pcan:usb1
await using var node = J1939Node.Create(bus, o => o.ReadOnly = true);
node.MessageReceived += m =>
{
    if (m.Pgn == Pgn.Dm1) Console.WriteLine(string.Join("; ", J1939Dm1.Parse(m.Data).Dtcs));
    else if (J1939Spn.Knows(m.Pgn)) Console.WriteLine(m);   // "EEC1 from 0x00: …, Engine speed = 1168.625 rpm, …"
};
await node.StartAsync();                                   // mengklaim 0xF9 (alat diagnostik off-board)

var vin = await node.RequestAsync(Pgn.VehicleIdentification);    // jawaban multi-paket lewat transport protocol
Console.WriteLine(System.Text.Encoding.ASCII.GetString(vin.Data));
```

Untuk mendengarkan tanpa mengirim apa pun, pakai `J1939Node.Create(bus, o => o.ListenOnly = true)`. Buka juga
adapter dengan `o.ListenOnly = true` bila adapter mendukungnya.

## Keamanan

Request tidak berbahaya, tetapi node J1939 yang mengklaim alamat ikut serta dalam jaringan. `ReadOnly = true`
membatasi node hanya pada request: `SendAsync` melempar `ReadOnlyModeException`, sehingga aplikasi tidak bisa
mengirim perintah seperti kendali torsi/putaran TSC1. `ListenOnly = true` tidak mengirim apa pun, bahkan klaim alamat,
dan itulah pilihan yang tepat pada kendaraan yang sedang berjalan. Monitor CLI bersifat listen-only; `request` dan
`claims` hanya-baca. Hubungkan hanya ke kendaraan yang Anda berwenang tangani.

## Alat

```bash
iotcom j1939 monitor --can sim                      # ECU mesin simulasi
iotcom j1939 monitor --pgn eec1 --pgn dm1 --can socketcan:can0 --bitrate 250000
iotcom j1939 request vin --to 00 --can sim          # VIN lewat RTS/CTS
iotcom j1939 claims --can gsusb:                    # setiap alamat dan NAME di bus
```

## Pengujian

Uji codec mencakup:
- identifier untuk PDU1, PDU2, dan data page 1;
- tata letak bit NAME;
- penguraian SPN dengan nilai "tidak tersedia";
- DM1 dengan dan tanpa kode gangguan, termasuk SPN 19-bit;
- pesan kontrol transport protocol dan frame lane.

Uji sesi menjalankan node di jaringan virtual:
- klaim alamat dan siaran dari mesin;
- VIN lewat RTS/CTS, identifikasi komponen lewat BAM, dan jam operasi mesin dalam satu frame;
- kebocoran oli simulasi yang memunculkan DM1 dan lampu kuning;
- transfer RTS/CTS 1785 byte (255 paket);
- node yang kalah konflik alamat lalu pindah ke alamat kosong;
- penolakan mode hanya-baca, timeout request, dan node listen-only yang mengikuti transfer antara dua node lain.

Ke-28 vektor bersama dijalankan di suite uji C# dan Rust. Codec Rust di-fuzz sebanyak 2,9 juta kali tanpa temuan.

## Keterbatasan

Tabel SPN baru mencakup PGN mesin yang umum; PGN yang tidak dikenal tiba dengan data mentah. Belum didukung:
- extended transport protocol (ETP, lebih dari 1785 byte);
- penghapusan kode gangguan (DM3/DM11);
- fast packet NMEA 2000;
- multi-PG J1939-22 CAN FD.
